## Question

What concrete Native Desktop page and interaction flow best supports one active Discovery Launch, read-only completed or failed history, Stop, Resume, and the still-undecided arrangement of the central runtime view with the reusable Progress, Artifacts, and Access modules?
The prototype must explore the layout rather than prematurely turn the current RightRail into a fixed Discovery design.

## Prototype

[Launch monitoring prototype](../prototype/launch-monitoring/README.md) contains three shareable UI variants.

Variant A uses a central runtime desk with a persistent Progress, Artifacts, and Access rail.

Variant B uses a history-first master/detail arrangement with explicit read-only selection.

Variant C uses a lifecycle stage strip, facts grid, raw console, and contextual rail.

The prototype simulates Stop and Resume for the single active Launch and keeps completed or failed Launches read-only.

The prototype is not a resolution; layout selection remains pending review.
