# 行业机器人学习“数据飞轮 / 自进化循环”一手来源

检索日期：2026-08-20。只采用论文、公司官方技术页面、官方文档和官方 GitHub。本文是给主报告使用的证据底稿，不把企业宣传中的“generalization / adaptation / self-learning”自动等同于生产系统中的在线持续学习。

## 结论先行

截至检索日，没有任何一家在公开材料中完整披露并可复现以下生产闭环：**已部署机器人自动采集 → 自动判断成功/失败 → 数据治理与风险分级 → 自动训练 → 仿真与真机安全门禁 → 自动灰度发布 → 事故回滚 → 再训练**。

公开材料中最接近完整路线的三组是：

1. **NVIDIA Isaac / GR00T**：公开组件覆盖遥操作采集、合成轨迹、世界模型生成与过滤、训练、仿真/真机评测、端侧部署和功能安全，但“部署反馈触发下一轮训练/自动晋级”仍不是一个公开的一体化产品闭环。
2. **Boston Dynamics Atlas LBM**：官方明确写出“采集 → 处理/标注/治理 → 训练 → 测试集评测 → 评测结果指导下一轮采集和架构选择”，是最清楚的迭代学习闭环；但它是研发团队控制的离线迭代，不是机器人在线自修改。
3. **1X**：官方在 2026 年直接给出“多源预训练数据 + on-policy NEO 数据 → 真机部署采集与 RL → 更多数据”的飞轮，并公开 1XWM 的 WM+IDM 训练配方；但没有论文、代码、安全晋级协议或自动反馈系统实现，证据级别仍是企业技术博客。

因此，更准确的行业术语应是 **fleet learning / iterative robot learning / data engine / human-in-the-loop continual improvement**。若把“自进化”定义为在线自主更新，公开证据不足。

## 统一判断口径

阶段：`采集 → 治理/回放 → 世界模型/仿真 → 训练 → 评测/安全门禁 → 部署 → 反馈 → 持续学习`。

- **真实机器人闭环**：至少存在真机采集、训练、真机部署/评测三个环节，并明确用新结果指导下一轮。
- **研发迭代闭环**：人决定数据、训练和晋级；模型不在生产现场自动改权重。
- **在线自适应**：机器人根据当前观测实时纠偏，但参数通常不更新，不能称持续学习。
- **在线持续学习**：部署期间新增经验进入训练并更新参数，还要有安全评测、版本晋级和回滚。公开项目基本没有做到最后一项。

## 商业/研究机构路线

### NVIDIA GR00T / Isaac Lab：公开组件覆盖最完整，仍缺统一反馈控制面

**公开事实**

- [GR00T N1: An Open Foundation Model for Generalist Humanoid Robots](https://arxiv.org/abs/2503.14734)，2025-03-18。公开 N1 论文与权重路线；[NVIDIA/Isaac-GR00T](https://github.com/NVIDIA/Isaac-GR00T) 当前公开仓库为 **N1.7 release**（2026-04-18，Apache-2.0），README 给出数据准备、微调、open-loop/仿真/真机评测、Policy API、ONNX/TensorRT 部署。
- [Building a Synthetic Motion Generation Pipeline for Humanoid Robot Learning](https://developer.nvidia.com/blog/building-a-synthetic-motion-generation-pipeline-for-humanoid-robot-learning/)，2025-03-18。GR00T-Mimic 路线为：少量遥操作/空间计算设备示范 → Isaac Lab 数字孪生 → Mimic 扩增物理轨迹 → Cosmos Transfer 增强外观 → 模仿学习。官方报告 11 小时生成 78 万条轨迹，并称与真实数据混合后 N1 性能提升 40%。
- [Enhance Robot Learning with Synthetic Trajectory Data Generated by World Foundation Models](https://developer.nvidia.com/blog/enhance-robot-learning-with-synthetic-trajectory-data-generated-by-world-foundation-models/)，2025-06-16。GR00T-Dreams：少量真机遥操作轨迹微调 Cosmos Predict-2 → 文本/初始图生成未来视频 → Cosmos Reason 过滤失败 dream → 逆动力学/轨迹生成 → 用合成轨迹训练真机策略。它比 Mimic 更接近“世界模型提出新任务数据”。
- [isaac-sim/IsaacLab](https://github.com/isaac-sim/IsaacLab)，当前版本 **v3.0.0-beta2.patch1**（2026-07-02，BSD-3-Clause）。公开 GPU 并行仿真、RL/模仿学习、传感器、30+ 环境和 sim-to-real 工具。
- [Inside NVIDIA Halos for Robotics: A Full-Stack Functional Safety System for Physical AI](https://developer.nvidia.com/blog/inside-nvidia-halos-for-robotics-a-full-stack-functional-safety-system-for-physical-ai/)，2026-06-22。公开独立安全计算、安全 OS、OOD/摄像头遮挡/连接异常监测，以及面向 IEC 61508、ISO 13849 等认证的框架。它可承担“安全门禁”，但不是 GR00T 自动模型晋级器。

**链路判断**

`采集(强) → 治理/格式(中强，LeRobot/模态元数据/rollout recording) → 仿真/世界模型(强) → 训练(强) → 评测(强) → 部署(强) → 反馈(弱公开) → 持续学习(未公开)`。

**真实闭环**：有真机训练/部署证据，也有 synthetic real-to-real 路线；但公开资料没有证明已部署机群自动回传、自动再训练、自动安全晋级。应称“组件级完整、编排闭环未公开”。

### Google DeepMind RT-X / Gemini Robotics：跨本体数据与模型强，产品级闭环不公开

**公开事实**

- [RT-2: Vision-Language-Action Models Transfer Web Knowledge to Robotic Control](https://arxiv.org/abs/2307.15818)，2023-07-28；[官方介绍](https://deepmind.google/blog/rt-2-new-model-translates-vision-and-language-into-action/)，同日。将动作表示为 token，与 web 视觉语言数据共同训练，并在真实机器人上评测泛化。
- [Open X-Embodiment: Robotic Learning Datasets and RT-X Models](https://arxiv.org/abs/2310.08864)，2023-10-13；[官方介绍](https://deepmind.google/blog/scaling-up-learning-across-many-different-robot-types/)，2023-10-03；[官方 GitHub](https://github.com/google-deepmind/open_x_embodiment)。数据统一为 RLDS，官方称来自 22 种机器人、33 个实验室，超过 100 万 episode、500+ skill、15 万 task；开放 RT-1-X checkpoint 和离线 inference 示例。仓库不是完整的真机训练—部署平台。
- [Gemini Robotics: Bringing AI into the Physical World](https://arxiv.org/abs/2503.20020)，2025-03-25；[官方介绍](https://deepmind.google/blog/gemini-robotics-brings-ai-into-the-physical-world/)，2025-03-12。Gemini Robotics 是直接动作 VLA，Robotics-ER 负责空间/具身推理并可接传统低层控制器；报告含跨本体、少样本微调、真机任务和分层安全讨论，并发布 ASIMOV 语义安全数据集。
- [Gemini Robotics On-Device brings AI to local robotic devices](https://deepmind.google/blog/gemini-robotics-on-device-brings-ai-to-local-robotic-devices/)，2025-06-24。低延迟本地推理，SDK 可在 MuJoCo 测试，并称可用 50–100 条示范适配；仅 trusted tester，不是开源栈。
- [Gemini Robotics 1.5 brings AI agents into the physical world](https://deepmind.google/blog/gemini-robotics-15-brings-ai-agents-into-the-physical-world/)，2025-09-25。ER 1.5 负责分解/规划/进度和成功估计，VLA 1.5 执行动作；ER 通过 Gemini API 开放，动作模型和训练流水线未开源。

**链路判断**

`采集(强但内部) → 治理(RLDS/OXE 强) → 仿真(中，MuJoCo SDK) → 训练(强但大多闭源) → 评测/语义安全(强研究证据) → 部署(真机/On-Device) → 反馈(未公开) → 持续学习(未公开)`。

**真实闭环**：真实机器人策略与跨本体训练成立；没有公开 fleet feedback、再训练触发、版本晋级/回滚。

### Physical Intelligence π0 / π0.5：开放模型适配链，非自动飞轮

**公开事实**

- [π0: A Vision-Language-Action Flow Model for General Robot Control](https://arxiv.org/abs/2410.24164)，2024-10-31；[Our First Generalist Policy](https://www.physicalintelligence.company/blog/pi0)，同日。以 VLM backbone + flow-matching action expert 处理多机器人、多任务、连续动作。
- [π0.5: a Vision-Language-Action Model with Open-World Generalization](https://arxiv.org/abs/2504.16054)，2025-04-22；[A VLA with Open-World Generalization](https://www.physicalintelligence.company/blog/pi05)，同日。面向开放场景长时程移动操作，混合异构机器人数据与高层语义知识。
- [Physical-Intelligence/openpi](https://github.com/Physical-Intelligence/openpi)，Apache-2.0，无正式 GitHub release tag。当前 README 开放 π0、π0-FAST、π0.5 基础权重和 DROID/ALOHA/LIBERO 专家模型，称基础模型预训练于 **10k+ 小时机器人数据**，提供自有数据微调与真机 inference 示例。

**链路判断**

`采集(内部，细节有限) → 治理(开源适配器/过滤示例) → 世界模型/仿真(非核心) → 训练/微调(强开源) → 评测(论文/基准) → 部署(真机示例) → 反馈/持续学习(无)`。

**真实闭环**：可人工完成“采集小数据—微调—真机部署”，没有自动收集失败数据、自动重训和安全晋级。

### Figure Helix：模型结构公开较细，数据飞轮与安全门禁闭源

**公开事实**

- [Helix: A Vision-Language-Action Model for Generalist Humanoid Control](https://www.figure.ai/news/helix)，2025-02-20。S2 为 7B VLM、7–9 Hz，S1 为 visuomotor transformer、200 Hz；约 500 小时多机器人/多操作员遥操作数据，VLM hindsight instruction 自动标注；全链路在机载低功耗 GPU 运行。
- [Introducing Helix 02: Full-Body Autonomy](https://www.figure.ai/news/helix-02)，2026-01-27。增加 1 kHz System 0 全身控制基础层，使用 1000+ 小时重定向人类动作数据，并在 20 万+ 并行仿真环境做 sim-to-real RL；S1 连接视觉、触觉、本体感知并输出全身关节目标，公开演示四分钟无人工干预的厨房任务。

**链路判断**

`采集(遥操作/人类动作，强) → 自动标注(有) → 仿真/RL(Helix 02 强) → 训练(架构级公开) → 评测(企业演示，协议不完整) → 真机部署(强) → 反馈/持续学习(未公开)`。

**真实闭环**：真机控制成立；无论文、代码、数据、标准测试集、失败回放/重训或安全晋级公开。企业演示不能证明生产式自进化。

### Tesla Optimus：只有平台级方向，无法从一手来源还原技术飞轮

**公开事实**

- [Tesla AI Day 2022](https://www.youtube.com/watch?v=ODSJsviD_SU)，2022-09-30，官方活动视频，公开 Optimus 原型、执行器、运动/感知与训练基础设施方向。
- [Tesla 2025 Form 10-K](https://www.sec.gov/Archives/edgar/data/1318605/000162828026003952/tsla-20251231.htm)，2026-01-29。Tesla 仅正式披露：使用视觉技术与自研推理芯片训练神经网络，把自动驾驶 AI 经验应用到 Optimus，并利用 real-world AI data 推进其开发；同时明确 Optimus 尚未商业化。

**链路判断**

`采集(推断可能共享视觉/数据基础设施) → 训练/部署(方向性披露)；治理、机器人数据规模、模型架构、仿真、评测、安全门禁、反馈、持续学习均未公开`。

不能把汽车 fleet learning 直接外推为 Optimus 已有同构飞轮；这属于推断，不是官方事实。

### Skild AI：仿真/互联网视频预训练路线明确，复现证据弱

**公开事实**

- [Building the general-purpose robotic brain](https://www.skild.ai/blogs/building-the-general-purpose-robotic-brain)，2025-07-29。Skild Brain 为低频高层策略 + 高频低层策略；以大规模仿真和互联网视频预训练，再用目标真机数据 post-train、fine-tune/distill 后部署。
- [The case for an omni-bodied robot brain](https://www.skild.ai/blogs/omni-bodied)，2025-09-24。宣称在 10 万种模拟机器人、约千年模拟时间上训练，展示未见本体的 zero-shot 鲁棒控制。“learns from failures”在材料中指当前策略的实时恢复/泛化，不等于在线参数更新。
- [Learning by watching human videos](https://www.skild.ai/blogs/learning-by-watching)，2026-01-12。主张用人类视频解决数据瓶颈，并称新技能可用视频 + 少于 1 小时机器人数据微调。

**链路判断**

`互联网视频/仿真(强宣称) → 真机少量 post-train → 部署；治理、标准评测、安全门禁、部署反馈和持续学习未公开`。

没有论文、代码、权重或可核验测试协议，成熟度只能判为“真机演示强、工程闭环不可审计”。

### 1X：公开路线最像“数据飞轮”，但仍是闭源技术博客

**公开事实**

- [1X World Model | From Video to Action: A New Way Robots Learn](https://www.1x.tech/discover/world-model-self-learning)，2026-01-12。公开 1XWM：14B 文本条件视频 WM，先 web-scale video 预训练，再用 900 小时 egocentric human video mid-train、70 小时 NEO 数据 fine-tune；另用 400 小时未过滤机器人数据训练 inverse dynamics model。推理为“初始图+文本 → WM 生成未来视频 → IDM 提取动作 → 真机执行”。使用 VLM caption upsampling、动作 DTW 指标选 checkpoint、人工审核生成视频的物理合理性/任务完成度/本体一致性。
- [1X Launches World Model Lab to Scale Humanoid Intelligence](https://www.1x.tech/discover/1x-world-model-lab)，2026-06-04。官方直接给出：`web media + egocentric human video + sim + remote-operated robot data + on-policy NEO data → real-world deployment for robot data collection and RL → abundance of data → physical AI`。

**链路判断**

`多源采集(强) → caption/人工接受与动作指标治理(中强) → 视频世界模型(强) → WM+IDM/RL 训练(强描述) → 真机部署(有) → on-policy 反馈(路线明确) → 持续学习(目标明确但自动化/安全晋级未公开)`。

**真实闭环**：这是一手来源中最直接的“真机部署产生 on-policy 数据，再进入 RL”的描述；但无论文、代码、数据、失败检测器、自动晋级/回滚和安全 case，不能视为已可审计的生产闭环。

### Agility Robotics Digit：生产部署最成熟之一，学习仍是离线发布

**公开事实**

- [Agility Robotics Expands Relationship with NVIDIA](https://www.agilityrobotics.com/content/agility-robotics-expands-relationship-with-nvidia)，2025-03-18。使用 Isaac Sim/Lab 做 RL 训练与测试、Mega/Omniverse 做客户场景数字孪生，并把策略部署到 Digit 的 NVIDIA 计算平台。
- [Agility and AI](https://www.agilityrobotics.com/content/agility-and-ai)，2026-03-16。公开数据来源：VR 遥操作、公司设施和客户部署数据、仿真；三层栈为高层任务推理、中层动作策略、底层 whole-body control foundation model；底层以 RL/仿真训练。页面明确“未来”通过云更新给部署机器人下发新技能。

**链路判断**

`真机/客户采集(强) → 仿真/数字孪生(强) → LfD+RL(强) → 生产部署(强) → 现场经验反馈(有) → 云技能更新(未来态) → 在线持续学习(无)`。

成熟度高在“商业部署和操作安全”，而不是自主学习。公开资料没有表明 Digit 在客户现场自动训练自己。

### Boston Dynamics：最清楚的研发迭代闭环；Spot 有生产反馈证据

**公开事实**

- [Boston Dynamics & TRI Announce Partnership](https://bostondynamics.com/news/boston-dynamics-toyota-research-institute-announce-partnership-to-advance-robotics-research/)，2024-10-16。目标是在 Atlas 上训练 TRI Large Behavior Models；真机多任务收集性能数据，再用于 LBM 训练，并以硬件和仿真做严格评测，同时研究人机交互和 safety/assurance cases。
- [Large Behavior Models and Atlas Find New Footing](https://bostondynamics.com/blog/large-behavior-models-atlas-find-new-footing/)，2025-08-20。官方明确四步：真机/仿真遥操作采集 → 处理、标注、治理 → 跨任务统一训练 → 测试套件评测；评测结果决定下一轮采什么数据、选什么网络/推理策略。策略为图像+本体感知+语言到全身动作的 diffusion transformer + flow matching，30 Hz，在 Atlas/MTS/TRI 数据上跨本体训练。
- [Starting on the Right Foot with Reinforcement Learning](https://bostondynamics.com/blog/starting-on-the-right-foot-with-reinforcement-learning/)，2024-03-19。Spot 用百万级仿真、数千小时仿真与真机运行验证后，才经软件更新部署到客户；官方明确继续利用收集的数据改进策略。这是公开材料中较可信的商业机器人 fleet feedback 例子。
- [Boston Dynamics & Google DeepMind Form New AI Partnership](https://bostondynamics.com/blog/boston-dynamics-google-deepmind-form-new-ai-partnership/)，2026-01-05。计划将 Gemini Robotics 与 Atlas 结合；属于研究启动，不是已完成闭环。

**链路判断**

`采集(强) → 治理(强) → 仿真(强) → 训练(强) → 硬件/仿真测试门禁(强) → 部署(Spot 强、Atlas 研究态) → 数据反馈(强) → 离线持续改进(强)；在线自动更新(无)`。

这是最适合作为“自进化循环图”的公开工程参照，但准确名称是**评测驱动的数据—训练迭代循环**。

## 开源项目按飞轮阶段归位

| 项目 | 主要覆盖阶段 | 真机闭环与成熟度 | 一手来源 |
|---|---|---|---|
| **LeRobot** | 机器人/遥操作接入、record、LeRobotDataset v3（MP4/Parquet、切分/删 episode/合并/Hub）、训练、仿真/真机 eval、部署；当前还集成 IL/RL/VLA/world/reward models | **最接近开源端到端骨架**，可人工形成真机迭代闭环；没有自动成功判定、数据风险治理、安全晋级和自动持续学习 | [huggingface/lerobot](https://github.com/huggingface/lerobot)，**v0.6.1，2026-08-03，Apache-2.0**；当前原生硬件列表含 **Unitree G1** |

## 证据化的参考技术路线

若要把模糊“自进化循环”落成工程图，公开材料支持的最小可信路线是：

1. **数据采集**：遥操作示范（DROID/LeRobot/Agility/Boston）+ 部署 on-policy 轨迹（1X/Boston Spot）+ 人类 egocentric video（π0/Skild/1X/GR00T）+ 仿真和 world-model 合成（Isaac/Mimic/Dreams/ManiSkill/RoboCasa）。
2. **治理与回放**：统一 episode schema（RLDS/LeRobotDataset）、时间同步/标定、任务与 hindsight label、失败/空闲过滤、数据 lineage、可重放；企业公开实例是 Figure 的 VLM hindsight label、1X 的 caption upsampling/人工接受和 Boston 的 process-annotate-curate。
3. **生成与仿真**：物理仿真用于可执行性和 domain randomization；视频世界模型用于扩大语义/场景覆盖；二者之间必须有 inverse dynamics、仿真 replay 或真机短测，不能把“看起来合理的视频”直接当动作真值。
4. **训练**：跨本体预训练 + 目标本体 post-train；高层 VLM/VLA 与高频 visuomotor/whole-body controller 分层是 Figure、Skild、Gemini 1.5、Agility 的共同趋势。
5. **评测与安全门禁**：离线 open-loop → 仿真 benchmark/stress test → 硬件测试架 → 限速/限力真机 → 小机群灰度；必须把 semantic safety 与 motor/functional safety 分开。Gemini ASIMOV 解决前者，NVIDIA Halos/传统安全控制器解决后者。
6. **部署**：本地低延迟策略、明确版本、可观测、可回滚；不要现场直接在线改权重。
7. **反馈与持续改进**：上传低置信、人工接管、失败、边界条件和代表性成功样本；评测结果决定下一轮采集，Boston 的公开四步循环是最可靠模板。
8. **重新训练与晋级**：训练是离线批次，只有通过不回归、OOD、接触力、碰撞、稳定性、长时程成功率等门禁后才晋级；“持续学习”应发生在受控训练面，而不是安全关键控制面。

## 最重要的取舍

- **不要把实时纠偏称为自进化**：Helix/Skild/RT-2 的 reactive control 是 inference-time adaptation，不代表模型权重更新。
- **不要把合成视频直接称为新技能数据**：必须经过物理/动作一致性过滤。1X 使用 IDM+动作 DTW+人工接受；GR00T-Dreams 使用 Cosmos Reason 过滤并生成轨迹，这是两个公开范式。
- **开源世界里没有一个仓库包办全部**：最现实组合是 `LeRobot（采集/格式/训练/部署骨架） + DROID（真机采集范式） + robomimic（回放/离线训练） + Isaac Lab 或 ManiSkill（仿真） + RoboCasa/RoboVerse/BEHAVIOR（任务与门禁） + OpenVLA/Octo/openpi/GR00T（策略）`。
- **真正缺口不在 VLA，而在控制面**：数据质量、失败归因、测试门禁、版本晋级、回滚、机群观测和安全 case，公开项目仍碎片化。
